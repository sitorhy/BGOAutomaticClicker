# 助战合成流水线 NarrowFigureChain

## 输入参数
+ work_dir: Path，单个从者目录 `res/assets/{dir_name}`；narrow_figure_chain = NarrowFigureClassifyChain(work_dir).output()，读 narrowFigure/ascension 与 narrowFigure/costume
+ fg_dir: Path，前景素材目录，默认 RES_DIR / "foreground_support"（下文 FG_DIR 指它；原「input_dir」与 work_dir 含义撞车，已改名区分）
+ chain_offset: (11, 12)，立绘相对画布左上角的落点。实测 narrowFigure 素材全部是 148x375、前景图层全部是 170x400，(170-148)//2=11、(400-375)//2=12，所以默认值本身就是居中落点
+ mask: Path, 助战掩码图，一般不需要（数据源已经有助战专属立绘省了裁剪步骤），为 narrow_figure_chain 输入设置透明通道，默认 None。传入时用 RES_DIR / "mask" / "助战框掩码.png"：它是画布尺寸（170x400）的亮度掩码，alpha 通道整张都是 255，必须 convert("L") 取亮度、且在立绘落位之后按画布坐标套，不能 resize 到 148x375（掩码白区 bbox (12,14)-(159,388)，正是切角后的立绘区）
+ output_dir: Path，输出目录，产物写 output_dir/{dir_name}
+ servant: 分路依赖 card_rarity（归一化成 金卡/银卡/铜卡/铁卡，空串归 铁卡，同 composite.py 的 _group_of）与 servant_class（职阶徽标文件名）

## 输出逻辑简述
narrow_figure_chain 分别叠加在背景序列上，根据 card_rarity 进行分路，
card_rarity = "金卡"，那么背景合成就选用 config['金卡'], narrow_figure_chain 分别和 '金' 和 '冠位' 分流
根据偏移（默认 (11, 12)）将 narrow_figure_chain 的图片移动到背景图的 x= 11, y=12 的位置覆盖在上面。
得出助战背景序列 narrow_figure_frame_chain, 使用跟头像合成类似的管理方式（非必须）：
[
       {"name": "金", "narrow_figure_frame_chain":  NarrowFigureFrameChain(...).output() },
       {"name": "冠位", "narrow_figure_frame_chain": NarrowFigureFrameChain(...).output() },
]
当执行下一个序列时候，根据 card_rarity 取出分支配置，在取出对应分路的 narrow_figure_frame_chain 作为下一级的输入

## 阶段与 Chain 类命名
命名沿用头像流水线的「阶段名 + Chain」风格，加 NarrowFigure 前缀表示助战链路，与头像侧的同名类区分开（两张卡面尺寸不同：助战画布 170x400，头像画布 280x280）。

| 阶段 | 图层 | 类名 | 输入序列 | 输出序列 |
| --- | --- | --- | --- | --- |
| 输入筛选 | - | NarrowFigureClassifyChain（已存在） | res/assets/{dir_name}/narrowFigure | narrow_figure_chain |
| 背景 | L0 | NarrowFigureFrameChain | narrow_figure_chain | narrow_figure_frame_chain |
| 边框前景 | L1 | NarrowFigureBorderChain | narrow_figure_frame_chain | narrow_figure_border_chain |
| 标签前景 | L2 | NarrowFigureLabelChain | narrow_figure_border_chain | narrow_figure_label_chain |
| 星级 | L3 | NarrowFigureStarsChain | narrow_figure_label_chain | narrow_figure_stars_chain |
| 职阶徽标 | 徽标 | NarrowFigureClassChain | narrow_figure_stars_chain | narrow_figure_class_chain |
| 礼装合成 | 礼装掩码 | NarrowFigureCraftChain | narrow_figure_class_chain（主链最终卡面，不是筛选出的立绘） | narrow_figure_craft_chain |
| 汇总 | - | PostChain（复用头像侧，不改名） | narrow_figure_class_chain | 助战卡面（中间产物，仅作礼装合成底板） |

说明：
+ L0 与 L1 都是「框」，但语义相反：L0 垫在立绘下方当背景，L1 覆盖在立绘之上描边。L1 若也叫 Frame 会和头像侧的 FrameChain（= 背景框）撞语义，故用 Border。
+ L1~L4 四类都是「输入序列 × 图层列表」的笛卡尔叠加，图层尺寸已是画布 170x400，直接继承 OverlayChain（layer_on_top=True、skip_existing=False）即可，只需实现 overlay_layers / output_name。
+ NarrowFigureFrameChain 不能套 OverlayChain：OverlayChain 会把图层 resize 到 target 尺寸，而这里要把 148x375 的立绘按 chain_offset 贴到 170x400 的 L0 背景上（(170-148)/2=11、(400-375)/2=12，即默认偏移就是居中偏移），缩放方向是反的。它接受 bg_nodes（L0 序列）+ target_nodes（narrow_figure_chain）+ offset，参照 FaceMixChain 的双序列形态。
+ 分路信息只落在类名参数里，输出文件名靠头像侧的 rank_name/class_name 机制带出分组，否则各路产物会互相覆盖。
+ 输出命名沿用头像侧风格，且分组名必须写进最上游的 Frame 阶段 stem，后续阶段只加自己的层号：
```
NarrowFigureFrameChain  {stem}_{group}_{name}_{target_idx}.png          例 800100@0_金卡_金_3.png
NarrowFigureBorderChain {stem}_border_{layer_idx}_{target_idx}.png
NarrowFigureLabelChain  {stem}_label_{layer_idx}_{target_idx}.png
NarrowFigureStarsChain  {stem}_stars_{group}_{name}_{layer_idx}_{target_idx}.png
NarrowFigureClassChain  {stem}_{class_name}_{layer_idx}_{target_idx}.png
NarrowFigureCraftChain  {stem}_craft_{bg_idx}_{target_idx}.png
```
  stem 来自 narrowFigure 文件名（800100@0 形式），实测同一 dir 的 ascension 与 costume 之间无同名 stem，所以 {stem} 在单个 dir_name 内唯一。
  Craft 阶段的 {stem} 是整条主链叠加后的长名，产物名最长（实测 85 字符），仍在安全范围。
+ 12 个从者目录没有 narrowFigure 子目录（483 个 assets 目录里只有 471 个有助战立绘；缺的是 83 149 151 152 168 240 333 411 412 436 443 460）。缺目录属于素材不全，在枚举待处理目录阶段就警告跳过，不进 record、不抛错。

## 编排入口与落盘
+ 新建 `src/chaldea/composite_support.py`，暴露 `composite_support(input_dir, sub_dir_filter, output_dir, record_file, max_workers, db_path)`，签名与 composite() 对齐；Servant 实体、CompositeRecord、_group_of、_servant_id_of 等直接复用 composite.py 里已有的实现，不重复造一份。
+ 产物与头像素材同目录混放：output_dir/{dir_name}（默认仍是 TEMP_DIR），同一从者标签下增加卡面外观多样性。命名前缀靠 {stem}（800100@0 形式）与头像侧的 charaGraph stem（800100a@1 形式）天然区分，加上各阶段的 _border_/_label_/_stars_ 后缀不会撞名；OverlayChain._produced 的重名检测负责兜底告警。
+ 最终素材只取 narrow_figure_craft_chain 的结果：主链卡面（NarrowFigureClassChain → PostChain）降级为礼装合成的底板中间产物，链类照常落盘，但 `_process_work_dir()` 不把它放进返回值，record 里统计的张数即礼装图数。
+ 进度记录独立一份：TEMP_DIR / "composite_support.json"，与头像链的 composite.json 互不影响，可以单独删掉重跑。
+ CLI：`python -m chaldea support [dir_name ...]`，不带参数默认只跑 "1"，`support all` 跑全量；__main__.py 里按第一个参数是否为 "support" 分流到 composite_support()。

## 礼装合成（NarrowFigureCraftChain）
输入参数：
+ class_chain: NarrowFigureClassChain 的输出序列，即主链最终卡面（每张卡面各出一批礼装变体）
+ crop_mask: 默认 res/mask/礼装位置掩码.png
+ background_list: list[Path]，默认 res/background 下的图片
+ size: int，链类自身默认 10；编排侧由 `composite_support.CRAFT_SIZE` 传入，当前为 1，即每张卡面只出一个礼装变体
+ output_dir: Path，产物写 output_dir/{dir_name}

输出逻辑：
1. 在 background_list 中随机选 size 张背景图；尺寸不足以容纳 crop_mask 时，先把背景图拉伸到长宽都 ≥ crop_mask。
2. 按 crop_mask 的画布尺寸（170x400）在每张选中背景图的随机位置（不超出图片）截一块，把 crop_mask 的亮度通道设为这块切片的 alpha —— 切片只有掩码白区被保留下来，其余全透明。这一步得到 crop_chain。
3. 切片与卡面同为 170x400，直接对齐叠在卡面上（`Image.alpha_composite(卡面, 切片)`，不 resize、不偏移）。礼装窗位置因此显示随机背景，卡面其余内容原样保留。
4. 只写最终合成图到 output_dir/{dir_name}；切片是中间图层、只在内存里传递（同 BackgroundClipChain 的做法），落盘会往数据集目录里塞一堆近乎全透明的文件。

为什么盖在卡面上而不是立绘上：礼装窗 (11,245)-(160,315) 完全落在立绘区 (11,12)-(159,387) 内部，游戏里那块显示的是好友所带概念礼装，与本从者身份无关且不可控；用随机背景把它盖掉，模型就不会去学这块内容。吃主链最终卡面意味着边框、序号、星级、徽标这些特征都保留，礼装变体与卡面变体正交相乘。

实测素材事实：
+ 礼装位置掩码.png 是 170x400 画布尺寸的亮度掩码（alpha 整张 255，白区才是掩码），白区 bbox = (11, 245)-(160, 315)，即 149x70 的横窗，直角无羽化（只有 0/255 两级）。
+ 掩码画布尺寸 == 输出尺寸 == 卡面尺寸，所以切片不需要再缩放或二次裁剪，直接和卡面逐像素对齐；craft 阶段因此没有 offset 参数。
+ res/background 现有 50 张，最小 1075x1075，全部 ≥ 掩码尺寸，「拉伸」分支在当前数据下永不触发，只是防御性代码。
+ 随机性：切片位置与背景选图都用 random，跟 BackgroundClipChain 一致，不做种子固定；同一 dir 重跑会产出不同切片。

## 实现落点

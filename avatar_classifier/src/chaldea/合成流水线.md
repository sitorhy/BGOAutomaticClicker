# 完整的合成流水线 composite.py
## 输入参数：
+ 输入目录 input_dir: Path, 默认 RES_DIR / "assets"， 遍历子目录作为输入目录
+ 目录过滤函数 sub_dir_filter, 默认返回 true, (dir_name) => true， 用于过滤输入子目录， (dir_name) => dir_name == "1" 则只执行从者id为1的图片合成
+ 输出目录 output_dir，循环 input_dir 子目录 dir_name  的时候，将该子目录下的合成图片输出到 output_dir/{dir_name}
+ 处理记录文件 record_file: Path，默认 TEMP_DIR / "composite.json"，单独参数控制，便于反复测试时直接删除 temp 下的记录与产物重跑
+ 线程数 max_workers: int | None，默认 None（自动），按 dir_name 并行
+ 数据库路径 db_path: Path，默认 ROOT_DIR / "servants.db"

## output 输出流程：
1. 使用 sqlite3 链接本地数据库 DB_PATH = ROOT_DIR / "servants.db"，读取 servants 表数据，实体类参考 mooncell/train.py 的 Servant（含 dir_name 字段），在 chaldea/composite.py 内自建一份，不依赖 mooncell 包；读取 avatar 表，获取裁剪区域数据，avatar表结构参考 face-detect-server 子项目的 database.py。
2. 取出所有 input_dir 的子目录，然后用 sub_dir_filter 进行过滤 , 得到工作区目录序列 work_dir_list。 每个work_dir 目录名称对应一个从者id, 命名方式支持 "{servant_id}" 或分组形式 "{servant_id}_{number}"(例如 1_1 / 1_2 等)。
   前面数据库读取出来的 servants 列表实体类中有个参数 dir_name， 将  work_dir_list 映射为新的 servants 实体类列表（带dir_name）, 然后 servants 列表继续过滤掉 revoke = 1 的实体，得到最终的 servants列表。
   注意：dir_name 是输出目录与图片检索的键，servant_id 是数据库查询的键；分组形式下 id 取下划线前的数字段，两者不同。
3. 输出处理记录 record_file（默认 TEMP_DIR / "composite.json"）, 格式:
```
[  {servant_id: number,  dir_name: string, servant_cn: string, completed: number  }  ]
```
其中 servant_cn 取自 servants 表的 name_cn 列。
每个 dir_name（work_dir） 处理完后，将对应记录的 completed 设为1， 已处理的直接跳过以下流程；处理过程中抛异常的保持 0，下次重跑。读写需要支持线程同步，建议单独一个类封装操作，json文件不存在时候自动创建一个。
4. 遍历 servants 对于每个 dir_name（work_dir） 执行流水线操作， 以下的流程都是针对单个 dir_name 描述的, 因为每个dir_name 可以使用多线程并行输入处理
5. dir_name 输入 CharaClassifyChain 输出立绘序列 chara_chain，例如：
```
res\assets\1\charaGraph\ascension\800100a@1.png
res\assets\1\charaGraph\ascension\800100a@2.png
```
6. chara_chain 逐张输入 ExpandClipChain，得到 expand_chain（list[ChainNode]）。ExpandClipChain 的 target_img 是 Path 而非 ChainNode，故对 chara_chain 每个节点各构造一条（传 node.image_path），再把各条链 output() 的结果按顺序拼接为 expand_chain。
avatar 的表的数据样例为，
```
id 4055
servant_id 483
file charaGraph/ascension/406000b@2.png
left 205
top 146
right 365
bottom 306
```
chara立绘图片的相对 input_dir 的路径为 {dir_name}/{file}，即 avatar.file 是相对 work_dir 的路径。匹配方式：把图片路径相对 work_dir 取子路径（统一成正斜杠）后与 avatar.file 精确比对，查询键用 dir_name 解析出的 servant_id。立绘在 avatar 表查不到 rect 属于数据缺失，直接抛错，不做静默跳过。
下面是 ExpandClipChain 参数来源说明， mask_img 使用 RES_DIR / "mask" / "BGO头像裁剪掩码.png"
```
target_img = chara_chain 每个节点的 image_path
rect=(left, top, right, bottom) 由上一步的路径匹配 avatar 表得到
ratio=160 / 160（mask_img 的宽高比，此处即 1.0）
min_scale=0.85
max_scale=1.5
steps=3
output_dir=output_dir / {dir_name}
mask_img = None （这里不输入 mask_img，掩码留到 FrameChain 阶段套）
```
ExpandClipChain 输出后得出 expand_chain。steps=3 时每条链实际产出 4 个裁剪节点（steps 个线性插值 scale 之外还附加基准 scale=1.0，重复 rect 会去重），文件名形如 {立绘文件名}_bg_{idx}.png。

12. 各路 ClassChain 汇成 PostChain 作为单个 dir_name 的最终输出（后处理作用暂留空）。

13. 背景混合阶段（在 12 之后执行，产物与主链路并列作为训练素材）：
+ StatusClassifyChain(work_dir) 取该目录的 status 图片序列（status/ascension、status/costume，256×256）作为前景；序列为空时打印黄色提示并跳过本阶段。目前 483 个目录里只有 148 个有 status 图片。
+ BackgroundClipChain(BG_DIR, output_size=(280, 280)) 每目录现场随机裁剪 res/background 下的背景图，切片只以 ChainNode 内存形式传递，不落盘；原图小于切片时打印黄色提示并跳过该张。
+ FaceMixChain(status_nodes, bg_nodes, output_dir=output_dir / {dir_name}) 输出 status_nodes × bg_nodes 的笛卡尔积，文件名 {status_stem}_mesh_{bg_idx}_{target_idx}.png。
融合方式沿用 mooncell/merge_chain.py BackgroundChainNode 的算法，画布大小以背景切片为准（280×280）：前景按 zoom=1.5 放大到 384×384 后做 radius=15 的高斯模糊副本，用「边缘白、中心黑」且带宽 margin=40 的渐变遮罩把边缘换成模糊图、中心保持清晰，整体透明度 alpha=0.95，最后以负偏移居中叠到背景切片上（前景超出画布的部分被裁掉）。
+ 该 dir_name 全部产出后才把 record 的 completed 置 1。

14. 头像复制阶段：FaceClassifyChain(work_dir) 取该目录的头像文件序列（faces/ascension、faces/costume，128×128），用 CopyChain(input_nodes, output_dir=output_dir / {dir_name}) 原样复制到合成图同一目录（shutil.copy2，文件名保持 f_8001000.png 这样的原名）。
已核对 483 个目录共 2050 个头像，单个目录内 ascension 与 costume 之间不存在同名文件，直接按原名复制不会互相覆盖；头像数与合成图数无关，属于「按 dir_name 取素材时一并可用」的对照输入。

## 数据现状核对（编写实现前已验证）
+ res/assets 共 483 个目录，全为纯数字，暂无 {servant_id}_{number} 分组形式目录；分组分支按第 2 步规则实现即可。
+ avatar 表 4043 行：其中 2046 行为 charaGraph/ascension/xxx@2.png 形式的相对路径，与 res/assets 下的立绘 1:1 全覆盖（每张立绘都能查到 rect）；另 1997 行是早期手工标注的裸文件名（如 玛修·基列莱特-卡面-1-v2.png），对应文件已不在 assets 中，属于永不命中的历史数据，因此匹配口径只认相对路径。
+ servants 表 card_rarity 取值为 金卡 / 银卡 / 铜卡 / 空串；revoke=1 共 11 条，其中非 revoke 且 card_rarity 为空串的只有 id 107（Avenger，黑卡Avenger.png 存在）。
+ res/assets 内 ascension 与 costume 两个子目录之间不存在同名 stem，{stem}_bg_{idx}.png 命名在单个 dir_name 内不会冲突。
+ 规模提示：每张立绘产出 steps+1=4 个裁剪，金卡从者 3 路 × label 最多 2 层 × stars 最多 4 层 × class 1 层，单个 dir_name 的产物量约为 立绘数 × 4 × 分路基数 × label 层数 × stars 层数，全量跑前建议先用 sub_dir_filter 限定少数从者验证。
